There are 198 bytes starting at (loaded) address $3BFD.  See
player-explosion-data.hex for contents.

The structure seems to be 33 records of 6 bytes each:

struct ExplosionFragment {
    int16_t offset_0;
    int16_t location;  // Initialised when player ship hit
    int8_t  d_location_per_frame;
    uint8_t pixel_bitmask;
};

And we further interpret offset_0 and d_location_per_frame as
coordinates rather than raster address, i.e., as an (x, y) tuple, to
get:

    offset_0    dloc/frm   pxls
    ( 0,  0)    ( 0, -3)    11
    ( 1,  0)    ( 0, -4)    11
    ( 2,  0)    ( 0, -2)    11
    ( 0, -2)    ( 0, -3)    44
    (-1, -2)    ( 1, -3)    44
    ( 0,  1)    (-1, -3)    11
    ( 1,  1)    ( 1, -4)    41
    ( 2,  1)    ( 0, -4)    41
    ( 0,  5)    ( 1,  2)    41
    ( 1,  5)    (-1,  2)    41
    ( 2,  5)    (-1, -3)    44
    ( 0,  4)    ( 1,  0)    11
    ( 1,  4)    ( 1,  2)    44
    ( 2,  4)    (-1,  0)    44
    (-1,  5)    (-1,  0)    41
    ( 2,  5)    ( 1,  0)    41
    ( 0,  6)    ( 1,  3)    41
    ( 1,  6)    (-1,  4)    11
    ( 2,  6)    (-1, -3)    11
    ( 0,  7)    ( 0,  3)    44

The x-coords here are in bytes (so four double-width pixels).  The
y-coord increases down the screen.

The distinct pixel values are

    11 = G Y G Y
    14 = G Y Y G
    41 = Y G G Y
    44 = Y G Y G

so these are the four costumes needed.
